### Почему PASS недостаточно

- Broken images только выводятся; ненулевое количество не вызывает ошибку. Фильтр проверяет `!img.hidden`, но не CSS visibility/display, ancestor visibility или контекст появления. Незагруженный lazy может быть ошибочно назван битым; CSS-фоны и iframe этим фильтром не проверяются.
- Значения каталога/чипа/drawer/FAQ и текст черновика только логируются, не сравниваются с ожидаемыми. Достаточно присутствия элементов для выполнения действий.
- console error/warning собираются и выводятся, но не проваливают тест; pageerror/requestfailed и HTTP-ошибки отдельно не отслеживаются.
- Высоты всех четырёх viewport равны 900, мобильная высота 812 появляется только при финальных скриншотах.
- Финальные скриншоты делаются после формы/FAQ, без явного возврата наверх. Имя mobile-hero.jpg само по себе не гарантирует, что снят hero.
- Не выполняются действия калькулятора/подбора, проверки формул, открытие меню, focus trap, возврат фокуса, аудио, пауза/reduced motion или отправка/получатель сообщений.

## Фактический вывод human-design-audit.js

При 375×812/DPR2: headerHeight56, heroBottom812; все четыре флага видимости title/phone/CTA/bike равныtrue; dock visible:true, height68.875. Напечатано `Найдено мелких кликабельных зон на телефоне: 0`. При 1440×900/DPR2 сохранены полный экран и 12 секций.

Ограничения измерений:

- В заголовке обещано 44×44px, фактический порог — `width < 40 || height < 40`. Поэтому элементы 40–43.99px не попадают в замечания. Ни любое число замечаний, ни ложный above-fold-флаг не проваливают команду.
- Элементы с offsetParent===null исключаются. Это может исключить fixed-position элементы и не является полной проверкой видимости/доступности. Закрытые drawer/меню и состояния после взаимодействия не открываются и не измеряются.
- Флаг телефона проверяет только наличие rect и bottom≤812. Rect скрытого display:none элемента также может иметь bottom0, поэтому true не доказывает видимый телефон. Аналогично CTA/bike проверяются только по top<812, без ненулевой площади/декодирования/перекрытий.
- Контраст WCAG не вычисляется: JSON содержит CSS color/fontSize/fontWeight/lineHeight/letterSpacing, без цвета фона и contrast ratio. Визуальная иерархия и anti-slop-качество алгоритмом не оцениваются.
- Блоки `viewports`, `uxFlowObservations`, `recommendations` остаются пустыми. Список sectionsAudited означает наличие секций и полученные изображения, не содержательную приёмку.

Таким образом 0 мелких зон означает только 0 измеренных в этом проходе видимых по условию offsetParent зон меньше 40px. Это не подтверждение 44×44, WCAG или всей функциональности.
